## Complete workflow example

This example demonstrates a complete workflow: creating categories, products, services, and clients.

### Step 1: Create a category

```bash
curl -X POST http://localhost:8000/categories \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Electronics",
    "description": "Electronic devices and accessories"
  }'
```

Response:

```json
{
  "id": 1,
  "name": "Electronics",
  "description": "Electronic devices and accessories"
}
```

### Step 2: Create a product in that category

```bash
curl -X POST http://localhost:8000/products \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Laptop",
    "category_id": 1,
    "price": 999.99,
    "stock": 50
  }'
```

### Step 3: Create a service

```bash
curl -X POST http://localhost:8000/services \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Technical Support",
    "description": "24/7 technical support for all products",
    "price": 99.99
  }'
```

### Step 4: Create a client

```bash
curl -X POST http://localhost:8000/clients \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ABC Corporation",
    "client_id": "abc-corp-001",
    "legacy_id": 5001,
    "secret_name": "abc-corp-secret"
  }'
```

### Step 5: Retrieve all data

```bash
curl http://localhost:8000/clients
curl http://localhost:8000/products
curl http://localhost:8000/categories
curl http://localhost:8000/services
```

## Error handling example

Handle a missing resource gracefully:

```bash
curl http://localhost:8000/clients/00000000-0000-0000-0000-000000009999
```

Response (404):

```json
{
  "error": "not found"
}
```

In Python:

```python
import requests

response = requests.get('http://localhost:8000/clients/00000000-0000-0000-0000-000000009999')

if response.status_code == 404:
    print("Client not found")
elif response.status_code == 200:
    client = response.json()
    print(f"Found client: {client['name']}")
```

## Python client example

A simple Python function to interact with the API:

```python
import requests

BASE_URL = "http://localhost:8000"

def create_client(name, client_id=None, legacy_id=None, secret_name=None):
    """Create a new client."""
    payload = {"name": name}
    if client_id:
        payload["client_id"] = client_id
    if legacy_id:
        payload["legacy_id"] = legacy_id
    if secret_name:
        payload["secret_name"] = secret_name
    response = requests.post(
        f"{BASE_URL}/clients",
        headers={"Content-Type": "application/json"},
        json=payload
    )
    return response.json()

def get_all_clients():
    """Retrieve all clients."""
    response = requests.get(f"{BASE_URL}/clients")
    return response.json()

def get_client(client_id):
    """Retrieve a specific client."""
    response = requests.get(f"{BASE_URL}/clients/{client_id}")
    if response.status_code == 404:
        return None
    return response.json()

def update_client(id, name, client_id=None, legacy_id=None, secret_name=None):
    """Update a client (full replacement)."""
    payload = {"name": name}
    if client_id:
        payload["client_id"] = client_id
    if legacy_id:
        payload["legacy_id"] = legacy_id
    if secret_name:
        payload["secret_name"] = secret_name
    response = requests.put(
        f"{BASE_URL}/clients/{id}",
        headers={"Content-Type": "application/json"},
        json=payload
    )
    return response.json()

def delete_client(id):
    """Delete a client. Returns True if successful."""
    response = requests.delete(f"{BASE_URL}/clients/{id}")
    return response.status_code == 204

# Usage
if __name__ == "__main__":
    new_client = create_client("Acme Corp", client_id="acme-123", legacy_id=1001)
    print(f"Created client: {new_client}")

    all_clients = get_all_clients()
    print(f"All clients: {all_clients}")

    updated = update_client(new_client["id"], "Acme Corp Updated", client_id="acme-123")
    print(f"Update result: {updated}")

    deleted = delete_client(new_client["id"])
    print(f"Deleted: {deleted}")
```

## JavaScript/Node.js example

A simple JavaScript helper for API calls:

```javascript
const BASE_URL = 'http://localhost:8000';

async function createProduct(name, price) {
  const response = await fetch(`${BASE_URL}/products`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ name, price })
  });
  return response.json();
}

async function getAllProducts() {
  const response = await fetch(`${BASE_URL}/products`);
  return response.json();
}

async function getProduct(productId) {
  const response = await fetch(`${BASE_URL}/products/${productId}`);
  if (response.status === 404) return null;
  return response.json();
}

async function updateProduct(productId, updates) {
  const response = await fetch(`${BASE_URL}/products/${productId}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(updates)
  });
  return response.json();
}

async function deleteProduct(productId) {
  const response = await fetch(`${BASE_URL}/products/${productId}`, {
    method: 'DELETE'
  });
  return response.json();
}

// Usage
(async () => {
  const product = await createProduct('Keyboard', 79.99);
  console.log('Created:', product);

  const all = await getAllProducts();
  console.log('All products:', all);
})();
```

## Feature flags workflow

This example shows how to enable per-client feature flags and use the reprocessing capabilities they unlock.

### Step 1: Create feature flags for a client

Enable event reprocessing by status for a client identified by `legacy_id`:

```bash
curl -X POST http://localhost:8000/client-feature-flags \
  -H "Content-Type: application/json" \
  -d '{
    "legacy_id": 5001,
    "reprocess_by_status_enabled": true,
    "payload_signature_enabled": false
  }'
```

Response:

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "client": "c9d8e7f6-5432-1098-abcd-fedcba987654",
  "reprocess_by_status_enabled": true,
  "payload_signature_enabled": false
}
```

### Step 2: Check current feature flags

```bash
curl "http://localhost:8000/client-feature-flags?legacy_id=5001"
```

### Step 3: List rejected events for the client

```bash
curl "http://localhost:8000/reprocess/rejected-events?legacy_id=5001"
```

Response:

```json
[
  {
    "event_name": "payment.created",
    "notifications": [
      {
        "webhook_id": "d4e5f6a7-b8c9-0123-4567-890abcdef012",
        "url": "https://example.com/webhook",
        "status": "rejected",
        "count": 15
      }
    ]
  }
]
```

### Step 4: Reprocess rejected events by status

```bash
curl -X POST http://localhost:8000/reprocess/by-notification-status \
  -H "Content-Type: application/json" \
  -d '{
    "legacy_id": 5001,
    "webhook_id": "d4e5f6a7-b8c9-0123-4567-890abcdef012",
    "status": "rejected"
  }'
```

### Step 5: Redirect rejected events to a new webhook

If the original webhook is no longer valid, redirect events to a different one:

```bash
curl -X POST http://localhost:8000/reprocess/by-notification-status/redirect \
  -H "Content-Type: application/json" \
  -d '{
    "legacy_id": 5001,
    "webhook_id_old": "d4e5f6a7-b8c9-0123-4567-890abcdef012",
    "webhook_id_new": "f1e2d3c4-b5a6-7890-1234-567890abcdef",
    "status": "rejected"
  }'
```

## Webhook filtering

This example shows how to use webhook filters to route different event subtypes to separate endpoints.

### Step 1: Create webhooks with filters

Create one webhook that receives only approved payments:

```bash
curl -X POST http://localhost:8000/webhooks \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "abc-corp-001",
    "event_name": "payment.created",
    "url": "https://example.com/approved-payments",
    "auth_type": "bearer",
    "headers": {
      "Authorization": "Bearer token-approved"
    },
    "filter": {
      "field": "$.payload.status",
      "type": "equals",
      "value": "approved"
    }
  }'
```

Create another webhook that receives only rejected payments:

```bash
curl -X POST http://localhost:8000/webhooks \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "abc-corp-001",
    "event_name": "payment.created",
    "url": "https://example.com/rejected-payments",
    "auth_type": "bearer",
    "headers": {
      "Authorization": "Bearer token-rejected"
    },
    "filter": {
      "field": "$.payload.status",
      "type": "equals",
      "value": "rejected"
    }
  }'
```

### Step 3: Filter by numeric or boolean values

Filter values are not limited to strings. You can match numbers or booleans when the corresponding mutator template field uses that type.

Filter by a numeric amount:

```bash
curl -X POST http://localhost:8000/webhooks \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "abc-corp-001",
    "event_name": "payment.created",
    "url": "https://example.com/exact-amount",
    "filter": {
      "field": "$.payload.amount",
      "type": "equals",
      "value": 1000
    }
  }'
```

Filter by a boolean flag:

```bash
curl -X POST http://localhost:8000/webhooks \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "abc-corp-001",
    "event_name": "payment.created",
    "url": "https://example.com/recurring-only",
    "filter": {
      "field": "$.payload.is_recurring",
      "type": "equals",
      "value": true
    }
  }'
```

<Note>
The filter value type must match the field type defined in the event's [mutator](/api-reference/mutators/create) template. For example, if the mutator defines `amount` as a number, pass a number — not a string like `"1000"`.
</Note>

### Step 4: Update a filter

To change a filter, update the webhook with a new `filter` object. The existing filter is replaced:

```bash
curl -X PUT http://localhost:8000/webhooks/aaa11111-2222-3333-4444-555566667777 \
  -H "Content-Type: application/json" \
  -d '{
    "event_name": "payment.created",
    "url": "https://example.com/approved-payments",
    "auth_type": "bearer",
    "headers": {
      "Authorization": "Bearer token-approved"
    },
    "filter": {
      "field": "$.payload.status",
      "type": "equals",
      "value": "completed"
    }
  }'
```

<Note>
Filter field paths must reference fields that exist in the event's [mutator](/api-reference/mutators/create) template. The exception is `$.event_type`, which you can filter on without a mutator.
</Note>

## Partial client updates

Use `PATCH` to update specific client fields without replacing the full record:

```bash
curl -X PATCH http://localhost:8000/clients/c9d8e7f6-5432-1098-abcd-fedcba987654 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ABC Corporation (Renamed)"
  }'
```
