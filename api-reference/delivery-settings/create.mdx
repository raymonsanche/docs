---
title: "Create delivery settings"
api: "POST /delivery-settings"
description: "Create a new delivery settings configuration"
---

Create a new delivery settings configuration that defines how events are routed to message queues for a specific client.

## Endpoint

```
POST /delivery-settings
```

## Request body

<ParamField body="client_id" type="string" required>
  Client identifier. Must reference an existing client.
</ParamField>

<ParamField body="legacy_id" type="integer" required>
  Legacy client identifier. Must reference an existing client.
</ParamField>

<ParamField body="event_name" type="string" required>
  Name of the event to configure delivery for. Must reference an existing event.
</ParamField>

<ParamField body="queue_name" type="string" required>
  Name of the message queue
</ParamField>

<ParamField body="queue_exchange" type="string" required>
  Message queue exchange name
</ParamField>

<ParamField body="queue_key" type="string" required>
  Message queue routing key
</ParamField>

<ParamField body="app_name" type="string" required>
  Application name. The combination of client, event name, and app name must be unique.
</ParamField>

## Request example

```bash
curl -X POST /delivery-settings \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "abc123",
    "legacy_id": 12345,
    "event_name": "payment.created",
    "queue_name": "payment-notifications",
    "queue_exchange": "events-exchange",
    "queue_key": "payment.created.abc123",
    "app_name": "payment-service"
  }'
```

## Response

```json
  "client_id": "abc123",

  "event_name": "payment.created",

  "created_at": "2026-01-15T10:30:00Z",

```

## Rules

- Both `client_id` and `legacy_id` must reference an existing client
- The `event_name` must reference an existing event
- The combination of client, event name, and app name must be unique

## Use cases

- Configure queue-based event delivery for a client
- Set up message routing for a new event type
- Add an additional delivery channel for an existing event
