---
title: "Get client feature flags"
api: "GET /client-feature-flags"
description: "Retrieve feature flag configuration for a client"
---

Retrieve the feature flag configuration for a specific client by `client_id`, `legacy_id`, or feature flag `id`.

## Endpoint

```
GET /client-feature-flags
```

## Query parameters

Provide at least one of `client_id` or `legacy_id` to identify the client.

<ParamField query="id" type="string">
  Filter by feature flag record UUID
</ParamField>

<ParamField query="client_id" type="string">
  Filter by client UUID
</ParamField>

<ParamField query="legacy_id" type="integer">
  Filter by legacy numeric client identifier
</ParamField>

## Request examples

Look up by legacy ID:

```bash
curl "http://localhost:8000/client-feature-flags?legacy_id=12345"
```

Look up by client UUID:

```bash
curl "http://localhost:8000/client-feature-flags?client_id=c9d8e7f6-5432-1098-abcd-fedcba987654"
```

## Response

<ResponseField name="id" type="string">
  Unique identifier for the feature flag record (UUID)
</ResponseField>

<ResponseField name="client" type="string">
  The internal client ID this feature flag is associated with
</ResponseField>

<ResponseField name="reprocess_by_status_enabled" type="boolean">
  Whether event reprocessing by notification status is enabled
</ResponseField>

<ResponseField name="payload_signature_enabled" type="boolean">
  Whether payload signature verification is enabled
</ResponseField>

### Success response (200)

When feature flags exist for the client:

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "client": "c9d8e7f6-5432-1098-abcd-fedcba987654",
  "reprocess_by_status_enabled": true,
  "payload_signature_enabled": false
}
```

### Empty response (200)

When the matching client is not found, the endpoint returns an empty array with a `200` status code instead of an error:

```json
[]
```

<Tip>
If you receive an empty array, verify the `client_id` or `legacy_id` you provided. You may need to [create the client](/api-reference/clients/create) first before configuring feature flags.
</Tip>

### Error responses

**400 — Bad request**

Returned when neither `client_id` nor `legacy_id` is provided:

```json
{
  "error": "bad request"
}
```

**No feature flags configured**

Returned when the client exists but has no feature flag configuration. Create one using the [create endpoint](/api-reference/client-feature-flags/create).

## Use cases

- Check which features are enabled for a specific client
- Verify feature flag state before toggling
- Audit client configurations
