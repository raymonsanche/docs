---
title: "Create webhook"
api: "POST /external/webhooks"
description: "Create a new webhook subscription for your account"
---

Create a new webhook to receive event notifications at a specified URL. The webhook is automatically scoped to your issuer account.

## Endpoint

```
POST /external/webhooks
```

## Request body

<ParamField body="url" type="string" required>
  Destination URL where notifications are delivered. Must be a valid URL.
</ParamField>

<ParamField body="event_name" type="string" required>
  Name of the event to subscribe to. Must reference an existing event.
</ParamField>

<ParamField body="headers" type="object">
  Custom HTTP headers to include with each notification request
</ParamField>

<ParamField body="auth_type" type="string">
  Authentication type for the webhook endpoint (for example, `bearer`, `basic`)
</ParamField>

<ParamField body="filter" type="object">
  Optional filter to limit which events trigger this webhook.

  <Expandable title="Filter properties">
    <ParamField body="filter.field" type="string" required>
      JSONPath expression for the field to filter on
    </ParamField>

    <ParamField body="filter.type" type="string" required>
      Filter comparison type (for example, `equals`)
    </ParamField>

    <ParamField body="filter.value" type="string | number | boolean" required>
      Value to match. The type must match the corresponding field type in the event's mutator template.
    </ParamField>
  </Expandable>
</ParamField>

## Request example

```bash
curl -X POST /external/webhooks \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{
    "url": "https://example.com/webhook",
    "event_name": "payment.created",
    "headers": {
      "X-Custom-Header": "my-value"
    },
    "auth_type": "bearer",
    "filter": {
      "field": "$.payload.status",
      "type": "equals",
      "value": "approved"
    }
  }'
```

## Rules

- You must set up an encryption key before creating a webhook. Use the [save AES key](/api-reference/issuer/save-aes-key) endpoint to configure encryption first.
- The `url` must be a valid URL
- The `event_name` must reference an existing event
- You do not need to specify `client_id` or `legacy_id` — these are inferred from your authentication token
- Filter `field` must reference a field in the event's [mutator](/api-reference/mutators/create) template, unless the field is `$.event_type`
- Filter `value` type must match the mutator template field type (string, number, or boolean)

<Tip>
Use the [list events](/api-reference/issuer/list-events) endpoint to see which events are available before creating a webhook.
</Tip>
