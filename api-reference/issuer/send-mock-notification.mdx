---
title: "Send mock event notification"
api: "POST /external/trigger/mock"
description: "Send a notification using a predefined event mock payload"
---

Send a test notification using a predefined event mock payload. Instead of providing your own payload, this endpoint uses an existing event mock configuration. This endpoint is available in all environments, including production.

## Endpoint

```
POST /external/trigger/mock
```

## Request body

<ParamField body="event_name" type="string" required>
  Name of the event whose mock payload you want to send
</ParamField>

## Request example

```bash
curl -X POST /external/trigger/mock \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{
    "event_name": "payment.created"
  }'
```

## Response

### Success response (200)

```json
{
  "message": "test notification triggered successfully",
  "trace_id": "abc123-trace-id-001"
}
```

## Rules

- Available in all environments, including production
- The `event_name` must reference an existing event that has a configured event mock
- You must have at least one webhook configured for the specified event

## Use cases

- Quickly test webhook delivery without constructing a payload
- Use standardized mock payloads for consistent integration testing
- Verify end-to-end notification flow with realistic sample data
- Validate webhook delivery against your production environment using safe, predefined sample payloads

<Warning>
Calls to this endpoint trigger real webhook deliveries to your configured endpoints, including in production. Make sure your receivers can distinguish mock payloads from real events before testing in production.
</Warning>

<Tip>
Create event mocks using the [event mocks API](/api-reference/event-mocks/create) to define reusable test payloads for each event type.
</Tip>
